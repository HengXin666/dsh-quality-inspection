# 检测探针

各检测类的具体命令。**校准过的范例，不是照抄**：按项目实际调整文件 glob、排除目录、模式措辞。零命中不代表没货——先用已知正例验证模式有效，再信负结果。

## 历史叙述

持久散文叙述变更而非陈述现状。自然语言行加 `-i` 让句首大写命中；第一条代码形状的行保持大小写敏感。

```sh
rg -n -i 'used to |no longer|previously|the old |was renamed|was moved|has been deprecated' --glob '*.md' --glob '!vendor/**' --glob '!node_modules/**'
rg -n -i 'now (it|the|we)|in the past|originally|historically' --glob '*.md'
```

已知误报，判断后保留、不要修："the key used to sign requests"（工具义，非时间义）；"the old connection drains before the new one accepts"（运行时生命周期，非仓库历史）；`v1` 作为 URL 路径段或线上名（标识符，非版本戳）。

## 死引用

文档里的名字在代码里没有命中。先 grep 代码库知道哪些名字存在，再查仅文档命中：

```sh
rg -n '<符号或命令>' --glob '!*.md'          # 代码命中——名字还在
rg -n '<符号或命令>' --glob '*.md'           # 文档命中——对比
```

名字只在文档、不在代码 = 过期；两边都没有 = 名字本身是死的。

## 坏链接

遍历 markdown 链接和锚点。项目有检查器就用；没有就脚本探测语料（只算相对目标）：

```sh
# 列出全部相对 markdown 链接目标，再逐文件验证存在性
rg -o '\]\(([^)#]+)(#[^)]+)?\)' --glob '*.md' -r '$1'
```

别忘了片段（`#锚点`）：目标文件在、锚点可能已死。按项目用的方式（标题 slug 或显式 `<a id>`）验证锚点。

## 字数预算

只给易膨胀文件做（站立指令、架构文档、策略文档）——绝不每篇文档都做：

```sh
git ls-files '*.md' | xargs wc -w | sort -rn | head -20
```

预算棘轮收紧。一篇文档持续超限还不修剪，正是门要拦的膨胀。

## 重复事实

grep 特征短语；一个短语有两个家 = 重复发现项。选事实形状的短语，不要样板话：

```sh
rg -l '某个事实会用到的确切短语' --glob '*.md'
```

留一个家，其余换成链接——但合并前保留独有理由（输家按废弃规则处理）。

## 不编译的代码块

对文档里声称可运行或类型正确的 fenced 块，用项目自己的检查跑。门的形式：抽块 → 用项目工具链编译/执行 → 报错即失败。声称可运行却失败的块比没有更糟——修它，或降级说法。
