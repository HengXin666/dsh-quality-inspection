# 新鲜度审计

八类腐化、检测顺序、修复规则。每条发现都满足主文件的"路径+证据"标准。先分类，再决定修复还是废弃（废弃规则见 [deprecation.md](deprecation.md)）。

## 八类腐化

1. **死引用** —— 文档引用了代码里已不存在的符号、命令、配置键、包或文件。在代码库搜这个名字；只有文档有命中 = 过期。
2. **历史叙述** —— 文档写 "之前 / 现在 / 不再 / 改名为 / 移动到了 / 过去是"。当前状态属于文档，故事属于决策记录或提交。改写为当前状态，或把故事路由出去。
3. **版本混杂** —— 一个文件里混着多个版本的说明且没有版本机制。要么是当前状态（只写一版），要么需要真正的版本化机制。
4. **坏链接** —— 链接、锚点、交叉引用指向不存在的东西。跑检查器；每个死链都是发现项。
5. **不编译的代码块** —— 文档里声称可运行却跑不起来的代码块。能跑就跑一遍；"声称可运行却失败"比没有更糟。
6. **矛盾的决策记录** —— 记录描述的行为代码里已不存在。判断是哪个变了：决策仍立（更新记录的事实），还是决策被推翻（废弃记录）。
7. **中间产物** —— 草稿、以"已装"面目示人的提案、占位符 "TODO: 待补文档"、没有决策价值的废弃设计笔记。
8. **孤儿指令** —— AGENTS.md 级指令与真实命令、真实行为、真实结构不符。

## 检测顺序

先用最便宜的探针，再对每条命中做语义判断——探针有意过匹配，也天然会漏：

1. 全库搜历史叙述短语（命令见 [probes.md](probes.md#历史叙述)）。
2. grep 每个文档里"代码中只在文档出现、或哪里都不出现"的名字。
3. 跑链接检查器；锚点和交叉引用 grep 目标。
4. 编译或执行文档中声称可运行的代码块。
5. 无模式通读最密的散文（README、架构文档、站立指令）——探针抓不到的漏网在这补。

## 修复规则

- **死引用**：主题还在就改成当前名；主题没了就删掉该说法。
- **历史叙述**：改写为当前状态。已修复的回归写成现在时的反事实（"没有 X 就会 Y"），绝不写成仓库历史（"过去是 Y"）。
- **版本混杂**：选定当前版本写清楚；其他版本移入真正的版本化产物或决策记录。
- **坏链接**：指向真实目标，或删掉链接并改写它承载的事实。
- **不编译的代码块**：修到能编译，或把说法降级为实际成立的内容。
- **矛盾记录**：决策仍立就更新事实（同一决策、新实现）；决策被推翻就按废弃规则处理。
- **中间产物**：只在理由确证不承重时删除；否则按 [deprecation.md](deprecation.md) 归档或取代。
- **孤儿指令**：把指令改成现实，或删掉。站立指令每个会话都读——假指令比没有更贵。

## 什么时候不该修

发现项的主题是被**带着书面决策**故意删掉或改名的：不要复活文本，按决策更新文档事实或废弃文档。发现项碰行为、契约、架构的：那是提案，不是就地修复。
